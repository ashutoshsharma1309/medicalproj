# `lib/ml` — risk inference and explanation

The serving half of the ML feature. Training lives in [`../../ml/`](../../ml/README.md);
nothing here trains anything.

```
artifacts/*.json ──► artifact.ts ──► inference.ts ──► predict.ts ──► risk-service.ts
   (from Python)      (validate)      (score+SHAP)     (assemble)      (fetch, persist)
                                                            │
                                          features.ts ──────┘
                                        (Digital Twin → model inputs)
```

## Module map

| File | Purity | Responsibility |
|---|---|---|
| `types.ts` | — | Mirrors the Python artifact shape |
| `artifact.ts` | pure | Loads and structurally validates artifacts |
| `inference.ts` | pure | Scaling, logit, sigmoid, exact SHAP |
| `categories.ts` | pure | Risk banding and its wording |
| `confidence.ts` | pure | Measured-vs-imputed confidence |
| `predict.ts` | pure | Assembles a complete explained prediction |
| `features.ts` | pure | Digital Twin → model inputs |
| `validation.ts` | pure | Zod schema built from the artifact's own ranges |
| `twin-integration.ts` | pure | Predictions → Health Twin insights |
| `explanation-service.ts` | I/O | LLM narration, guardrailed, with a deterministic fallback |
| `risk-service.ts` | I/O | `server-only`. Fetch, orchestrate, persist |

Everything above `explanation-service.ts` is pure, which is why 70 of the
phase's tests run with no database, no network and no API key.

## The two things that must stay true

**1. The model predicts; the LLM only phrases.**

`explanation-service.ts` receives figures that were already computed and its
prompt contains nothing it could use to derive a different score. A language
model asked "how likely is this patient to develop diabetes" will answer
fluently and with no basis whatsoever. Every number a patient sees comes from
the logistic regression.

**2. Contributions reconstruct the score.**

SHAP for a linear model is closed-form, so `base_value + Σφ === logit` holds
exactly — no background sampling, no Monte Carlo, no run-to-run variance. The
parity tests assert this on every fixture along with agreement with Python's
`shap` library.

That identity is what makes the explanation honest rather than decorative:
the bars on the dashboard account for the figure completely, so there is no
hidden remainder the patient is not being shown.

## Confidence is not accuracy

`confidence` answers "how much of *this* prediction is about you?" — the share
of model weight carried by features read from the patient's own records rather
than substituted from the training mean. It is weighted by |coefficient|, so
missing glucose in the diabetes model costs far more than missing skinfold
thickness.

Model accuracy is separate and is shown beside it, on the model card.

## Retraining

```bash
cd ../../ml && .venv/bin/python train_all.py
```

Rewrites `artifacts/*.json` and `supabase/seed/model_metrics.sql`. Bump
`MODEL_VERSION` in `ml/prediction/export.py` whenever the feature set or the
training procedure changes — stored predictions reference it, and a patient
looking at an old assessment must be able to tell which model produced it.

Run `npm test` afterwards. The parity fixtures are regenerated by the same
command, so a genuine regression shows up as a failure in the artifact
integrity tests rather than in parity.
